# testdata-loader

This is a simple tool to load test data into a database. It is designed to be used in a CI/CD pipeline (or locally) to load test data into a database before running tests.

It can load data into a postgresdb or into kafka topics. It can also be extended to load data into other databases or systems.

It supports loading data from local directories, ZIP files, or OCI-compliant container registries.

## Installation

### From Source

To build the application from source, you need Go installed (reasonably current version, cf. `go.mod`) and the source repository (https://gitlab.nimbusplane.io/isynth/testdata-loader.git) checked out.

```bash
make build
# Binary will be available in ./build/testdata-loader
```

### From Package Managers

The application is also available through package managers.

#### Windows (scoop)

You can install the loader on windows using the scoop 
([https://scoop.sh](https://scoop.sh)) package manager.

You need to add the scoop bucket once if you don't already have it (it is published 
in the same bucket as the nimbus CLI lgtctl).

```powershell
scoop bucket add lgtnimbus https://github.com/lgtnimbus/scoop-bucket
```

Then you can easily install it using:

```powershell
scoop install lgtnimbus/testdata-loader
```

#### Linux / Apple (brew)

You can install the loader on Linux or Apple using the brew 
([https://brew.sh](https://brew.sh)) package manager.

```bash
brew install lgtnimbus/tap/testdata-loader
```

#### From Binary

You can download the latest binary for your local environment under:

[https://gitlab.nimbusplane.io/common/lgt/isynth/testdata-loader/-/releases/permalink/latest#release](https://gitlab.nimbusplane.io/common/lgt/isynth/testdata-loader/-/releases/permalink/latest#release)

## Configuration

Data Packages are generated by iSynth and either published to an OCI container registry
or you can directly download it from iSynth to your local machine (in zip format).

The data package as generated by iSynth comes with a pre-configuration which only needs
to be extended by the user regarding the connection information to the databases or kafka
brokers.

An example configuration which you should create locally (on inside your CI/CD job) 
looks like this:

```yaml
version: v1
targetServices:
  heimdallkafka:
    connection:
      host: "kafka.my_namespace"
      port: 9092
      schemaRegistryUrl: "http://apicurio.my_namespace:8080/apis/ccompat/v6/"
  clientdb:
    connection:
      host: "dcl-read-cache-db.my_namespace"
      port: 5432
      username: "postgres"
      password: "postgres"
      database: "client"
  taskdb:
    connection:
      host: "dcl-read-cache-db.my_namespace"
      port: 5432
      username: "postgres"
      password: "postgres"
      database: "task"
  portfoliodb:
    connection:
      host: "dcl-read-cache-db.my_namespace"
      port: 5432
      username: "postgres"
      password: "postgres"
      database: "portfolio"
  creditdb:
    connection:
      host: "dcl-read-cache-db.my_namespace"
      port: 5432
      username: "postgres"
      password: "postgres"
      database: "credit"
  channel_agreementdb:
    connection:
      host: "dcl-read-cache-db.my_namespace"
      port: 5432
      username: "postgres"
      password: "postgres"
      database: "channelagreement"
  bloxxkafka:
    connection:
      host: "kafka.my_namespace"
      port: 9092
      schemaRegistryUrl: "http://apicurio.my_namespace:8080/apis/ccompat/v6/"
```
Adjust to your local environment. You may remove services that you don't need
in your environment. You may add additional services if you need more.

## Usage

`testdata-loader --help` gives you a detailed help about the available commands and 
their respective flags.

The most common command would be the `load` command.

An example call if your data package is stored locally (direct download from iSynth):

```bash
testdata-loader load --config path/to/config.yaml --source file:///path/to/data_package.zip --target heimdall --target client-db --target task-db
```

Assuming that your local config as described in the previous section is stored under `path/to/config.yaml`
and the data package has been downloaded from iSynth to `/path/to/data_package.zip`, this command
reads the data package and loads data into the heimdall kafka and the client and task service postgres
read caches. You can add more services by adding more `--target` arguments.

If you wish to load a data package which has been published towards an OCI compliant container registry,
the corresponding call looks like this:

```bash
testdata-loader load --config path/to/config.yaml --source oci://registry.nimbusplane.io/project/data_package:1.2.3 --target heimdall --target client-db --target task-db
```

If the registry requires authentication, you can set tokens using the following environment variables:

```
LOADER_OCI_REGISTRY_USERNAME=Private-Token
LOADER_OCI_REGISTRY_PASSWORD=<your nimbus token>
```


## Requirements

Version 1.0.0 of the testdata loader is a full rewrite and contains breaking changes.

It can only load data packages which have been
generated by iSynth / lgt_model >= 30.6.4
or the dcl constellation chart installation >= 
2.41.1.
